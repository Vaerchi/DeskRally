# CLI recording through the installed service

`agent_host stream --recording-service` enables recording requests for an ordinary-user CLI without elevating that process. A compatible installed DeskRally service must already be running with `allow_cli_recording: true` in its protected `config.json`. This setting defaults to false and is read at service startup. It authorizes local interactive users to consume the bounded recording facility; enabling it is an administrator decision. No installation, configuration change or elevation is performed by the CLI.

The service writes recordings beneath `C:\rmt-agent\cli-recordings`, in generated per-recording subdirectories. The actual directory is returned in the recording acknowledgement/audit. The caller cannot select a path, file name, retention interval, device identity for authorization, or OS handle. Device/session UUIDs describe the client's stream; they are not authenticated central audit evidence. Files remain restricted to SYSTEM and Administrators. The ordinary CLI is not granted direct file access or an export facility.

`--recording-dir <path>` retains its existing direct-recorder behavior and permission requirements. It cannot be combined with `--recording-service`. Neither option starts recording by itself: signed policy or the existing StartRecording command triggers recording. Without either option, CLI recording remains unavailable. Attended recording remains unavailable. Installed-helper direct recording remains unchanged.

If the service is missing, disabled, busy or incompatible, a recording request fails explicitly; there is no local-storage fallback and no automatic elevation. An optional recording failure returns an error. A mandatory recording failure terminates the session through the existing fail-closed path. Writer or connection failure is observed through the recorder's stopped state; the host must not continue a mandatory-recording session without a writer.

The service permits one broker recording at a time, at most 1 GiB per recording, 256 segment transitions, one hour, and the existing 2 GiB free-space floor. It reserves capacity against a 4 GiB working-storage budget and rejects unexpected storage entries. Encoded frames are limited to 2 MiB, messages are length-bounded before allocation, and the encoder hands data to an eight-frame nonblocking queue. Queue overflow or oversized frames stop recording and mark truncation. Disk, protocol, disconnect and time-budget failures also preserve a failure/truncation outcome; they never acknowledge successful recording after failure.

Retention uses the existing 72-hour interval. The service expires completed recording directories based on the newest directory/file modification time (including the finalized sidecar). Maintenance runs before new broker recordings and every minute while the broker is idle; an active recording can delay idle maintenance by up to its one-hour limit. It does not parse sidecars as deletion instructions. The broker pins and checks storage directories' owner, DACL and reparse attributes before traversal. A suspicious directory fails closed and requires administrator investigation.

The local pipe rejects remote clients, restricts client data rights without granting pipe-instance creation, and authenticates an interactive client token. The client uses identification-only security QoS and verifies SYSTEM ownership on the connected pipe handle before sending stream data. The service owns the first pipe instance throughout its lifetime. Existing transport authentication/session-policy checks are unchanged.

## Validation status

Focused parser, queue, identity-rejection and lifecycle tests pass. On 2026-10-01, a bounded physical test ran the actual broker under SYSTEM and the actual client under an unelevated interactive token. One synthetic frame was recorded and finalized without truncation; direct directory access by the client was denied. Independent inspection confirmed SYSTEM/Administrators-only storage access. The temporary scheduled task exited and was removed. This validates the IPC/container path, not decoding or real desktop capture.

The nine historical Windows privilege-dependent tests also passed under Administrator without skips. A signed static-CRT agent update was exercised on an existing installation, preserving configuration and identity. The installed recording opt-in remains off. Forced service crashes, blocked-disk shutdown, fresh-machine Setup/cancellation, and display hotplug are not covered by these checks; do not infer those guarantees from the successful local tests.
